Did the agent have the whole document?

An AI agent writes “I reviewed the agreement; there is no early-termination clause.” Its copy may have been cut off at a length limit, or a retrieval step may have handed it some sections and not others. The sentence reads the same either way. This page asks the agent for six lines of the document, one from each sixth of the text, chosen by a hash of the agent’s own sentence. A copy that is short, or has a hole in it, cannot supply them.

Step one: the document

Paste the text, or choose a text file. It stays in this browser tab: the page makes no network request with it.

The copy keeps every line of four words or more, in order; line numbers refer to it, so the agent must work from this copy. The manifest holds one short hash per line and none of the text; with it, anyone can check a proof without having the document.

Already have a manifest?

Step two: the agent’s sentence

The finding exactly as the agent reports it. One changed character draws six other lines, which is why a proof cannot be prepared before the sentence is written or moved to another sentence.

Step three: check the proof

Paste the proof line the agent returned (it starts with ⟦READ:).

What happened when it was first tried

A real supply agreement filed with the SEC was given to four agents with the same question about termination without cause. The agent with the full text answered correctly and its proof held. The agent with the first three fifths answered that no such clause existed, which is wrong, and could not complete a proof. The agent whose copy had a stretch missing from the middle answered correctly and believed five of its six lines were good; two were, because every line after the gap had moved, and it had not noticed the gap. An agent told to invent the lines it lacked declined to. Each condition was run once with one small model; the record is in first-runs.json.

For agents and scripts

The same three steps without this page: read_proof.py (Python, no dependencies) and read-proof.js (browser or Node). The format is written down in Reading Proof 0.2. The two implementations are checked against each other daily.

What a proof shows and what it does not. It shows that whoever wrote the proof line could read those six places in the document after the sentence was written. It does not show that the sentence is true, that the document was understood, or that every line was read: an agent that opens the file and looks up only the six lines passes. It is a check on missing text, which is a common and silent failure, not on reasoning. An answer is four words, so a manifest in the hands of someone determined to forge a proof is weaker than the document itself; where forgery is the concern, keep the manifest with the party doing the checking.
